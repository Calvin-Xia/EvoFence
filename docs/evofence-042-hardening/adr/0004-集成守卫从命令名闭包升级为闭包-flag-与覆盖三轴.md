# 0004 — 集成守卫从命令名闭包升级为闭包、flag 与覆盖三轴

集成守卫升级为三轴：命令名闭包，即集成提到的命令必须存在于目录清单；flag 闭包，即集成提到的 flag 必须存在于该命令的 flag 集合；目录覆盖，即目录清单里的每条命令必须被至少一个集成覆盖，或在白名单里给出理由。被扫文件面从五份扩到全部集成说明文件。

**Status：** accepted

**Context：** 现有守卫只做命令名闭包，实测确认 flag 漂移可以绿灯通过，JS 插件调用的数字参数被正则捕获却从不被断言，且没有任何覆盖断言。这正是只读预检、账本离线校验与美元预算键三个新表面长期零覆盖却无人发现的原因。

**Considered Options：** A 只补 flag 闭包，能挡住参数漂移但仍不解决新能力无人覆盖；B 闭包加 flag 加覆盖三轴并扩文件面，选中；C 再加发布期脚本做集成一致性，超出本轮范围且与测试守卫职责重叠。

**Why：** 覆盖轴是三个新表面零覆盖的直接对策，缺它则下次目录清单扩张仍会静默产生缺口。白名单机制保留了有意不覆盖的命令，例如含完整事件载荷的读命令属隐私边界，从而不必伪造覆盖。

**Consequences：** 代价是目录清单每次扩张都可能要求同步集成说明，维护负担上升，这是有意的：把静默缺口换成显式失败。被扫文件面扩大后，此前未被校验的四份集成说明若含错误调用会立即变红，需在同一节点内修正。
