# 0003 — 开放 map 的值域校验不关闭 map，只约束值的形状

capabilities 保持唯一开放 map 的语义：键名仍不预先穷举，未知键名仍是合法能力名而非拼写错误；新增的只是一层形状与值域校验，要求每个能力键的取值属于三种允许式或其显式否定形态。校验失败沿用既有配置失败码。

**Status：** accepted

**Context：** 实测确认 capabilities 未知子键在字段装配阶段被原样保留且零校验，因此 network 为数组、shell 为字符串、值为数字全部静默通过。同时配置面文档明确承诺 capabilities 是唯一开放 map，未知键名是能力名而不是拼写错误。

**Considered Options：** A 把 capabilities 改为闭合 map 并穷举能力名，直接违背既有承诺且会拒绝合法的自定义能力名；B 保持开放但为值增加形状校验，选中；C 不校验，维持现状。

**Why：** 开放与校验是两个正交维度：开放说的是键名集合，校验说的是值形状。把两者混为一谈正是今天零校验的来源。选 B 既守住既有的开放承诺，又关掉畸形值静默通过的缺口。

**Consequences：** 此前写入畸形值的合同在新版本会被拒，拒的是畸形值不是合法配置。配置面文档的开放与闭合 map 小节必须改写为开放指键名开放、值形状受校验，机器守卫随之更新，否则守卫会因文档与 schema 不一致而红。
