# 0001 — 配置面薄弱键按修文档、加值域校验、非破坏清理三路处置

对 7 个薄弱键分三路：一是 network、dependency_install、credentials 在请求路径上已按能力名参与判定，属文档定性错误，只纠正文档而不发明行为检测；二是为 capabilities 开放 map 的子键增加形状与值域校验，畸形值不再静默通过；三是三个 template-only 死键从合同模板删除，其中 shell.mode 连引用一并清空、两个 acceptance 键在 schema 中降为兼容旧配置的空操作。authority_ceiling 保持仅校验，不定义等级到能力的映射。

**Status：** accepted

**Context：** 盘点确证配置面文档把三个能力键写成不拦任何东西，而它们在请求路径上确为活门：能力判定经动态查表接入迭代主循环，既有 gate 装配测试必须把 network 置为 allow 才能得到 accepted。同一盘点实测确认 capabilities 未知子键零校验，network 为数组这类畸形值静默通过；又实测确认 acceptance 是闭合对象，未知子键判 INVALID_CONTRACT。

**Considered Options：** A 只修文档，改动最小但畸形值仍静默通过且死键继续以可配不生效的形态误导；B 三路并进并采用非破坏清理，选中；C 为 authority_ceiling 定义等级映射并为 credentials 新建检测点，需发明仓库中不存在的语义且无观测信号。

**Why：** 价值面全为收紧或去掉误导，没有任何一项放宽既有门禁。authority_ceiling 与 credentials 的强制语义在仓库中无依据可查，发明它属于新增契约而非补全缺口，不应由执行者单方决定。

**Consequences：** 代价是值域校验会拒绝此前静默接受的畸形值（属拒绝垃圾而非破坏合法配置），死键清理会打到既有 grep 型守卫与 gate 装配测试，配置面文档与两个 README 需同步。收益是配置面不再承诺不存在的开关，文档不再与行为相反。若将来真需行为级阻断，须另立 ADR 并先确定观测信号。
