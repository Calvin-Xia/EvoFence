# 0003 — doctor 只呈现既有判定，不引入新校验

evofence doctor 只调用 run 的 preflight 已经使用的同源检查与加载器，逐条呈现其结论与原有错误码，不新增任何校验分支、不引入第二真相、不做更严格的额外体检。

**Status：** accepted

**Context：** run 的昂贵失败（不支持的预算组合、无法终止进程树、策略文件不合法、账本不可用）都要在派发 agent 之后才暴露，用户此时已经付出成本；而这些判断在 prepareRun 中已经完整存在，只是没有只读的呈现入口。

**Considered Options：** A doctor 自带一套更严格的体检规则，落选：两套规则必然漂移，且属于没人要求的多余校验；B 只读复用既有判断并逐条呈现，选中；C 不做 doctor 只靠文档提醒，落选：昂贵失败仍然会在付费之后才暴露。

**Why：** 复用在用户为 agent 付钱之前就给出与 run 完全相同的结论，不存在与 run 行为漂移的可能；同时符合不新造冗余校验的约束。

**Consequences：** doctor 的覆盖面只能等于 run 的拒绝面，未来新增拒绝项必须在同一处登记，测试需要锁定二者的对应关系；doctor 必须保持严格只读，否则会污染它自己要检的环境。
