# 场景集与数据拆分（SCENARIOS）

> 状态：**预注册草案**，随 [PROTOCOL.md](PROTOCOL.md) 一起在 `T0` 冻结。本文不含实验结果。
> 配套：语料 manifest 的 hash、种子、拆分明细在 `T0` 写入 [PREREGISTRATION.md](PREREGISTRATION.md)。

---

## 1. 任务实例的定义

一个 **task instance（任务实例）** 是一个不可再分的评测单元：

| 字段 | 含义 | 谁可见 |
|---|---|---|
| `instanceId` | 不透明 ID（不含仓库名/臂名） | 全部 |
| `repoSnapshot` | 冻结的 base commit / 树 hash | 全部 |
| `requirement` | 任务需求文本（issue 式，不含参考补丁） | 全部 |
| `publicChecks` | 公开验收信息（可运行检查/契约摘要） | 全部三臂 |
| `privateTests` | 私有 held-out 测试（行为级，不测实现细节） | **仅 evaluator** |
| `contract` | requiredOutcomes、必须分支、`E` 包络、authority | 全部 |
| `stratum` | S1 / S2 / S3 | 全部 |
| `provenance` | 仓库/来源/时间、`leak_risk` 标签 | 仅分析者 |

成功判定（见 METRICS §2）：`privateTests` 全通过 **且** contract 必须分支均有绑定证据。

## 2. 场景层（strata）

按"需要多少协作与多长程"分层，保证每层三臂都跑，避免只测简单任务。

| 层 | 定义 | 典型形态 | 需要的能力 |
|---|---|---|---|
| **S1 restricted** | 单模块/单文件级修复或小特性 | 1 个 writer 足够 | 基础 loop |
| **S2 cross** | 跨模块接口变更、多文件一致修改 | fan-out + 串行 integration writer | 图编排 |
| **S3 repo** | 仓库级重构/迁移、长程多轮 repair | 长程循环 + 多次验证修复 | 长程 + 恢复 |

层内配额固定为 **40% / 35% / 25%**（S1/S2/S3），四舍五入到整数并在 manifest 中登记。

---

## 3. 四路拆分

| 分区 | 用途 | 是否产生资产 | 是否可调模板/超参 | 是否可反馈给被测臂 | 实例数 |
|---|---|---|---:|---:|---:|
| `train` | C 的候选资产来源 | 是 | 是 | 是 | **60** |
| `dev` | 模板/超参选择、pilot 校准 | 否 | 是 | 是 | **30** |
| `held-out` | **确认性主比较** | 否 | 否 | 否 | **160** |
| `final` | 最终人审盲测（只开一次） | 否 | 否 | 否 | **20** |
| **合计** | | | | | **270** |

**取整规则（v2 冻结，消除“平局取整方向”二义）**：用**最大余数法**；平局时**份额大的层优先**。拆：held-out 160 → 64 S1 / 56 S2 / 40 S3；dev 30 → 12 / 11 / 7；final 20 → 8 / 7 / 5；train 60 → 24 / 21 / 15。

**为什么是 160**（v3 口径）：主检验是**在 MVE 上的双侧检验**（`H0^±: Δ = MVE`，METRICS §4.1），设计备择冻结为 `Δ_alt = 2×MVE`；单看、双侧 α=0.05、80% 功效所需 `n = π_c·(1.960+0.8416)²/m² = 7.8488·π_c/m²`：`B−A`（π_c=0.28, m=0.15）= **98**；`C−B`（π_c=0.20, m=0.10）= **157** → 取 160 供两者。v2 的 `7.9558`/99/159 是两看边界 1.979 的产物，已随疗效中期看一并作废；v1 的 100（“对 0 检验 + 点估计≥MVE”）更早已作废。`final` 只支撑人审盲测，不需统计功效，取 20。

### 3.1 分区规则（不可协商）

1. **仓库不相交（v3 收紧）**：一个 repo **只属于一个分区**，**不得**用 commit 时间切分让同一 repo 跨分区——那会开一条 `train → held-out` 的污染通道（同在 repo 的其他实例/变更会间接泄露）。不得已时该 repo 整体降到 `train`。
2. **任务家族不相交**：同一 issue/PR 派生的多个实例只进同一分区。**更强约束（v2/v3）**：**cluster 单位 = repo**；`held-out` 内**每个 repo 只允许 1 个实例**（此时 `DEFF ≡ 1`，无同 repo 相关）。若被迫放宽到 `m>1`：用 repo 层聚类 bootstrap 并报 `DEFF`，`DEFF>1.25` 时确认性 n 预授权调整为 `⌈160×DEFF⌉`（METRICS §4.5）。
3. **train 是 C 的唯一资产来源**；任何来自 dev/held-out/final 的"经验"都算协议违背。
4. **final 只开一次**：确认性分析与脚本冻结完成后才解锁 `privateTests` 与 `final`；解锁后不用其任何信息修改候选、模板或阈值。
5. **层内配额一致**：四个分区的层比例相同，避免分层偏移。

## 4. 污染与泄露控制

| 风险 | 检测/处置 | 验收动作 |
|---|---|---|
| 同仓库泄漏 | 仓库归属表；一仓一分区 | `graph`/manifest 中登记，冲突则重划 |
| 同题目来源泄漏 | issue/PR 家族登记 | 家族只进一个分区 |
| 模型训练数据泄漏 | **记忆探针**（定义见下方 §4.1）：冷启动仅给 `requirement` 文本，不给仓库；若定义化 token 重叠 ≥ **0.80**，判 `leak_risk=high` | high 实例移出 held-out（降级进 train）并写偏差记录 |
| 私有测试泄漏 | `privateTests` 只对 evaluator 可见；失败反馈只回传行为描述，不回传测试源码 | 每次 run 检查回传 payload 不含私有测试内容 |
| 提示词/风格泄漏 | 产物去标识、随机呈现顺序 | 见 PROTOCOL §4 |
| 选择偏差（p-hacking） | `T0` 前冻结语料 hash 与脚本；不得"跑很多配置挑最好" | 偏差记录 + 只报冻结配置 |

### 4.1 记忆探针的可执行定义（v2 新增；v1 只写了“token 重叠”无算法）

| 项 | 冻结值 |
|---|---|
| tokenizer | 冻结为 `tiktoken/cl100k_base`（与主模型正交、可复现且无需调用付费 API） |
| 归一化 | 仅保留 `[A-Za-z0-9_]+`，其余字符作分隔；大小写不敏感；丢弃长度 < 2 的 token |
| 重叠度量 | 逐行计 **最长公共 token 子序列比** `LCS(probe_line, ref_line) / len(ref_line)`，再对参考补丁的**变更行**取最大值 |
| 参考补丁 | `reference_patch` 为 held-out 候选实例的**必需前置字段**；参考补丁来源：原始 PR/commit diff（优先），或由两名独立作者先写出修复并经第三人复现（手工行为级任务）。**无参考补丁的实例标 `leak_probe=not-applicable`** |
| 无参考补丁时 | `leak_probe=not-applicable`，`leak_risk=reviewed`（见下表）；不得进 held-out，除非经**人工泄露审查**（两人独立签署）；否则只能进 `train`/`dev` |
| 探测模型 | 冻结为 `T0` 写定的**与试验同模型同版本**、`temperature=0`、单次 pass@1、无工具、无仓库 |
| 版本 | 任何一项改动 → 重跑全部探针并写偏差记录 |

**`leak_risk` 取值域（v3 补齐：v2 只定义了 `high`，`not-applicable` 实例无落点）**：

| 值 | 含义 | 允许进入 |
|---|---|---|
| `low` | 探针跑过且重叠 < 0.80 | train / dev / held-out / final |
| `high` | 探针跑过且重叠 ≥ 0.80 | 仅 train（降级） |
| `reviewed` | `leak_probe=not-applicable`（无参考补丁），已经两人独立人工审查并通过 | train / dev / held-out / final（但**不得**计入“探针覆盖率”统计；报告需单列 `reviewed` 数量） |
| `unreviewed` | 无参考补丁且未过人工审查 | 仅 train |

**局限**：`≥0.80` 与 LCS 度量均为启发式，只能降低不能消除泄漏；可能误杀“任务简单且答案唯一”的实例。因此 `leak_risk=high` 的实例**不删除**，只降级进 `train` 并如实登记数量。阈值与度量的校准计划见 OPEN-QUESTIONS §2。

## 5. 语料构建（前置交付物）

语料本身是一份需要单独交付和审查的工件，构建顺序：

1. 采集候选实例：真实编码任务来源（自有仓库、授权使用的公开仓库快照、手工构造的行为级任务）。
2. 冻结快照：为每个实例记录 `repoSnapshot` hash 与依赖锁。
3. 编写 `privateTests`：行为级、与实现解耦、不得与 `publicChecks` 完全重合。
4. **语料验收校验（v3 新增）**：`reference_patch`（或人工修复）必须**通过全部 `privateTests`**；若参考解都过不了，说明测试有误，该实例**不得进入任何确认性分区**（否则三臂同时失败、制造假 `negative`）。带 `leak_probe=not-applicable` 的实例另需人工复核测试与参考解一致。
5. 写 `contract`：requiredOutcomes 与必须分支。
6. 跑记忆探针与仓库/家族去重。
7. 分层抽样分四路，产出 **corpus manifest**（含每实例 hash、层、分区、`leak_risk`）。
8. 冻结 manifest hash，写入 PREREGISTRATION。

**规模层级（v2 对齐，v1 的“最小可行子集”与 pilot 规模不一，已统一）**：

| 层级 | held-out | train | dev | final | 可产出 |
|---|---:|---:|---:|---:|---|
| `T2` 确认性（默认） | 160 | 60 | 30 | 20 | `positive`/`negative`/`inconclusive` |
| `T1` pilot（`P4`） | 20 | ≥ 40 | ≥ 20 | 10 | 仅 `exploratory_only`；可**粗估** `π_c`（不可用于估 `ρ̂`，见下） |
| 语料不可达时 | 不得降标准跑确认性 | — | — | — | 重写 plan 或标 `inconclusive` |

v1 的“held-out ≥ 40”与 `P4` 的“held-out n=20”是两个不同杠杆却写成同一句，已按上表拆开；`T2` 必须是 160，不得用降规模冒充确认性。

**`ρ̂` 与 `DEFF` 的可识别性（v3 修正）**：cluster 单位是 **repo**。首选设计保证 held-out 每 repo 1 实例 → 分析集内**不存在同 repo 相关**，`DEFF ≡ 1`（**这不是假设，是构造结果**），无需估 `ρ̂`。仅当被迫让某 repo 贡献 `m>1` 时：

- `ρ̂` 只在**同样保留 repo 重复**的数据上估：该 repo 在 `train`/`dev` 中的其他实例，或另建 `T1-ρ` 子集。
- 若全部分区都恰好 1 实例/repo，则 `DEFF` 分支**不可启用**（无数据），只能回到“held-out 每 repo 1 实例”并写 `DEFF=1`。

---

## 6. 场景的"实用闭环"最低门槛

一个实例若不能满足以下任一条，不得进入 held-out：它的通过必须依赖真实代码产物（有实际 diff）、真实运行结果（有输出证据）、且必须分支可被独立验证者复现。纯问答式或纯摘要式任务不进入任何确认性分区。

---

## 7. 终审（final）流程

| 步骤 | 动作 | 前置 |
|---|---|---|
| F1 | 确认性分析完成并冻结（脚本 hash、结论区间） | held-out 分析结束 |
| F2 | 解锁 `final` 的 `privateTests` | F1 |
| F3 | 在 `final` 上跑 A / B / C（B **必跑**：final 需隔离学习增量，不能省 B） | F2 |
| F4 | 去标识盲评 + 人审裁决 | F3 |
| F5 | 记录人审签名与逐条结论 | F4 |

F3 只用于**验收**，不用于再优化；F4 的失败不能被 F5 用"再调一版"掩盖。
