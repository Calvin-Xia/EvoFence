# 0006 — 双宿主同等准入与显式差异

建议 DSH 与 Pi 各有 native session/delegation 实现和相同语义 contract suite；必须都完成真实闭环。差异通过 manifest 与 task requirements 解释。

**Status：** proposed（待裁决）

**Context：** 用户拒绝 DSH 优先/Pi 次之，要求同等首发。现有官方接口不同且版本可能漂移。

**Considered Options：** 只读 tools 或 CLI integration 快但无实用性；要求 API 完全一致不现实；语义 parity 可测且允许实现不同。

**Why：** 同等价值目标由场景与合同成立，不由工具数量成立。

**Consequences：** 双线维护与实验开销增加；若必要功能缺失需人审方案，不偷偷降级某宿主。
